# 一期：黑色基础投递闭环

## 1. 阶段目标

一期完成从招聘官网岗位发现到人工确认投递的最小可信闭环。用户可以输入一个校园招聘官网或社会招聘官网链接，在浏览器中登录自己的账号，读取岗位、解析JD、生成定制简历，并辅助填写申请表。

本阶段先用一个用户、一个指定官网、一个岗位验证纵向闭环，再逐步覆盖下表模块的完整能力；总框架完成不等于所有功能已实现。实际任务、依赖和验收证据以 [一期实施与验收任务台账](10_一期实施与验收任务台账.md) 为准。

## 2. 一期范围

| 模块 | 交付内容 |
|---|---|
| M00 | 用户权限、任务状态和操作审计 |
| M01 | 用户资料、目标岗位和城市偏好 |
| M02 | 实习、项目、技能和证据事实库 |
| M03 | 招聘官网链接和浏览器当前会话读取 |
| M04 | 岗位列表和JD页面读取 |
| M05 | 岗位字段标准化和基础去重 |
| M07 | JD结构化解析 |
| M08 | 岗位匹配、证据和风险说明 |
| M09 | 精准、平衡和覆盖投递模式 |
| M10 | 岗位定制简历生成 |
| M12 | LaTeX编译、错误和版面检查 |
| M13-M15 | 表单识别、辅助填写和人工确认 |
| M16 | 投递台账和基础状态管理 |

## 3. 一期流程图

```mermaid
flowchart LR
    A[用户资料与事实库] --> B[输入招聘官网]
    B --> C[浏览器登录]
    C --> D[读取岗位列表]
    D --> E[解析JD]
    E --> F[岗位匹配]
    F --> G[生成定制简历]
    G --> H[LaTeX编译检查]
    H --> I[识别申请表]
    I --> J[填充低风险字段]
    J --> K[用户确认高风险字段]
    K --> L[用户处理验证码]
    L --> M[用户最终提交]
    M --> N[写入投递台账]
```

## 4. 一期硬性边界

系统不得保存招聘网站密码，不得自动读取手机验证码，不得绕过滑块验证，不得在用户未确认的情况下提交申请。简历生成不得修改事实库中的受保护字段。

## 5. 一期验收

用户使用真实招聘官网完成至少一次岗位读取、JD解析、简历生成、PDF编译、网页辅助填写和人工确认后的投递记录创建，系统能够完整保存岗位来源、材料版本和投递状态。
