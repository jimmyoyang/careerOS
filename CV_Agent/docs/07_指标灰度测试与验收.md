# 指标、灰度测试与验收

## 1. 核心指标

| 阶段 | 核心指标 | 验收口径 |
|---|---|---|
| 一期 | 岗位关键字段提取准确率 | 公司、岗位、地点、链接和招聘批次等关键字段能够被正确提取，并允许用户手动修正。 |
| 一期 | JD核心要求识别准确率 | 系统能够区分职责、硬性要求、优先条件和出勤限制，并保留原始JD供用户核对。 |
| 一期 | 匹配结果可解释率 | 每个匹配结论都能够关联用户事实、JD要求和主要风险，而不是只输出无依据的分数。 |
| 一期 | 简历事实错误率 | 公司、岗位、日期、学校、数字和语言成绩等受保护事实不得被错误修改或虚构。 |
| 一期 | PDF编译成功率 | 用户确认生成的简历能够完成LaTeX编译，并通过页数、溢出和关键内容检查。 |
| 一期 | 网页字段识别准确率 | 系统能够区分低风险字段、高风险字段和需要人工操作的验证字段。 |
| 一期 | 投递记录完整率 | 每条已提交申请都能够记录岗位、来源、时间、简历版本和当前状态。 |
| 一期 | 用户完成一次投递的平均时间 | 在不降低材料审核质量的前提下，用户完成一次完整投递所需的时间逐步下降。 |
| 一期 | 高风险安全事件 | 关键事实虚构、用户密码保存和未经确认的最终提交次数必须为零。 |
| 二期 | 单次批量岗位处理时间 | 用户选择多个岗位后，系统能够在可接受时间内完成岗位解析、排序和任务生成。 |
| 二期 | 重复填写减少比例 | 与手动填写相比，系统能够减少用户重复输入教育、实习和项目字段的次数。 |
| 二期 | Outlook状态识别准确率 | 系统能够识别投递确认、笔试、面试、补材料和拒信等邮件，并保留原始邮件入口。 |
| 二期 | 多网站页面适配成功率 | 在已支持的招聘网站中，岗位列表、JD页面和申请表能够完成稳定识别。 |
| 二期 | 重复投递拦截率 | 系统能够根据公司、岗位、批次和链接识别已有申请，并在提交前提醒用户。 |
| 二期 | 用户任务完成率 | 用户能够按照提醒完成笔试、面试和补材料任务，并更新申请状态。 |
| 三期 | 有效内推信息识别率 | 系统识别的内推信息能够正确关联公司、批次、岗位和来源。 |
| 三期 | 过期内推码拦截率 | 系统能够根据发布时间、招聘批次和用户确认结果标记可能过期的内推码。 |
| 三期 | 公开信息来源可追溯率 | 每条推荐的内推信息都能够回到原始帖子、文档或用户提供的来源链接。 |
| 三期 | 用户对推荐内推码的确认率 | 用户能够查看来源、发布时间和适用范围，并在确认后才将内推码加入投递记录。 |
| 三期 | 个性化策略有效性 | 系统能够根据用户历史投递和面试结果调整推荐排序，并解释调整原因。 |

## 2. 灰度计划

| 阶段 | 用户规模 | 测试范围 | 通过条件 |
|---|---:|---|---|
| 个人验证 | 1人 | 1至2个招聘官网和20个真实岗位 | 完成岗位读取、JD解析、简历生成、PDF编译和投递记录创建。 |
| 小范围测试 | 5至10人 | 3至5种岗位方向和多个官网页面 | 用户能够理解匹配理由，并完成至少一次完整投递流程。 |
| 效率灰度 | 20至50人 | 多网站、批量岗位和Outlook只读同步 | 批量任务、网站适配、邮件识别和状态提醒稳定运行。 |
| 智能扩展测试 | 50至100人 | 群文档、公开内推和多设备同步 | 来源可追溯，内推信息经过用户确认，历史数据能够支持策略调整。 |

## 3. 一期验收场景

用户提供一个真实招聘官网，完成浏览器登录，选择岗位，解析JD，生成岗位定制简历，成功编译PDF，打开申请页面，辅助填写低风险字段，手动完成验证码和最终提交，并在系统中生成完整投递记录。
