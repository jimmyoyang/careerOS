# 用户与需求分析

## 1. 用户范围

CareerOS 允许不同类型求职者使用同一套核心流程，通过投递模式和筛选条件适配不同目标。

| 用户类型 | 典型场景 | 主要需求 | 首期支持程度 |
|---|---|---|---|
| 应届生与实习生 | 同时申请多个校招和实习岗位 | 岗位筛选、材料适配和投递记录 | 重点支持 |
| AI 与互联网岗位求职者 | JD 对 Agent、数据和产品能力要求差异明显 | 基于事实库调整简历重点 | 重点支持 |
| 精准投递用户 | 只申请少量重要岗位 | 深度分析 JD 并准备材料 | 支持 |
| 批量投递用户 | 希望扩大机会面 | 批量读取、排序和快速填充 | 二期重点支持 |
| 转行求职者 | 申请多个不同方向 | 判断可迁移能力和经历证据 | 支持 |
| 多渠道内推用户 | 使用官网、内推链接、招聘群和文档 | 管理来源、邀请码和申请状态 | 二期和三期扩展 |
| 有经验求职者 | 岗位数量较少但准备成本高 | 管理复杂面试和沟通流程 | 后续支持 |

## 2. 用户任务

用户需要从分散的招聘来源中发现岗位，判断岗位是否符合自己的硬性条件和发展方向，再根据 JD 选择真实经历，生成可信材料，完成网页申请，并持续追踪笔试、面试和邮件状态。

## 3. 用户需求优先级

| 需求层级 | 用户问题 | 产品回应 |
|---|---|---|
| 发现岗位 | 我提供的官网上有哪些岗位适合我？ | 读取岗位列表并提取结构化字段 |
| 判断岗位 | 这个岗位值不值得投入时间？ | 输出匹配结论、证据、风险和下一步 |
| 准备材料 | 我的经历应该怎样针对这个岗位表达？ | 从事实库生成岗位定制简历 |
| 完成申请 | 如何减少重复填写，同时避免填错？ | 浏览器辅助填写并保留人工确认 |
| 跟踪结果 | 我投了什么，下一步是什么？ | 投递台账、邮件状态和任务提醒 |

## 4. 投递模式

| 模式 | 适用情况 | 系统行为 |
|---|---|---|
| 精准模式 | 目标岗位少、单个岗位准备时间较长 | 生成完整匹配分析、简历和面试准备建议 |
| 平衡模式 | 日常秋招和实习申请 | 先筛选岗位，再逐个生成材料并确认 |
| 覆盖模式 | 希望扩大岗位覆盖面 | 批量读取和排序岗位，逐条确认最终投递 |

## 5. 需求验证方法

在邀请外部用户前，先用真实岗位完成个人验证，再邀请 5 至 10 名用户测试。访谈和测试需要覆盖精准投递、批量投递和多渠道内推三种场景，重点记录岗位判断、简历修改、表单填写和投递追踪各环节的真实耗时。
