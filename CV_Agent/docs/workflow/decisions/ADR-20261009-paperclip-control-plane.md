# ADR-20261009：Paperclip 作为中期 Agent 协作控制面

日期：2026-10-09  
状态：accepted_for_validation  
范围：`CV_Agent` 多 Agent 简历系统

## 背景

当前系统需要让产品、事实库、JD 分析、简历适配和 QA Agent 通过任务状态、交接和冲突记录协作，减少用户手动转发消息。候选方案包括 Paperclip、LangGraph、Microsoft Agent Framework、AG2、MetaGPT 和 Codex，但它们承担的层级不同，不能只按“谁更强”排序。

## 决策

中期采用 **Paperclip 作为 Agent 团队控制面**，并与以下组件配合：

```text
Paperclip：任务、负责人、状态、评论、审批和审计
Codex：本地文件、代码、测试和编译执行
MCP Policy：工具权限和敏感动作拦截
Git Worktree：并行任务隔离
Git/CI：Diff、合并和质量门禁
CV_Agent 文档：事实、契约、证据和裁决依据
```

当前不引入 LangGraph 作为必需依赖；只有出现复杂分支、跨运行恢复、节点级暂停/重试或需要持久化语义仲裁状态时，才重新评估。

## 选择理由

1. Paperclip 更适合管理“谁负责什么、当前做到哪、下一步交给谁”，能够减少用户作为通信中转站的负担。
2. LangGraph 更适合业务流程状态机，不应承担组织管理、预算和权限控制。
3. Codex 已经是当前实际执行面，不需要为了多 Agent 概念再替换执行器。
4. AG2 和 MetaGPT 可以参考其对话协作或角色 SOP，但不满足本项目对事实追溯、文件隔离和简历 QA 的首要要求。
5. Microsoft Agent Framework 只有在 Azure/.NET 或企业部署约束出现时才具有明显优先级。

## 边界与不变规则

- Paperclip 的状态不是事实库，也不是最终验收证据。
- Agent 不能因为 Paperclip 任务已标记完成而跳过事实 QA、LaTeX QA 或用户确认。
- 同一文件仍只有一个写入者；任务锁不能替代 Git Worktree 和 Diff 审查。
- 账号密码、Cookie、验证码、邮箱内容和真实投递权限不进入 Paperclip 任务交接记录。
- Paperclip 不可用时，系统必须能够退回本地任务卡和结果包模式。

## 验证门槛

在将状态从 `accepted_for_validation` 改为已运行前，必须完成：

- 只绑定 `127.0.0.1` 的健康检查；
- 脱敏任务创建、分派、评论和结果交接；
- 同一写入范围的冲突记录；
- 停止/重启后的任务状态恢复；
- 不配置外部模型、邮箱、招聘网站和真实浏览器会话；
- Paperclip 故障时的本地任务卡回退；
- 独立 QA 对以上结果出具运行报告。

## 影响

正面影响是减少人工中转、统一任务状态和审计入口。代价是增加本地控制面、版本管理和运行验证工作，因此当前只先验证脱敏任务和协作原语，不把框架部署误写成产品功能完成。
