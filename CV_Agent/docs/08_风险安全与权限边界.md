# 风险、安全与权限边界

## 1. 权限边界

| 场景 | 系统权限 | 用户操作 |
|---|---|---|
| 招聘网站登录 | 使用浏览器当前会话读取页面 | 用户本人输入账号、密码或完成扫码 |
| 岗位读取 | 读取用户主动打开或授权的页面 | 用户选择页面范围和岗位范围 |
| 简历生成 | 读取用户授权的事实库和JD | 用户审核生成内容 |
| 表单填写 | 识别字段并填充低风险字段 | 用户确认高风险字段 |
| 验证码 | 不读取、不代填 | 用户手动完成 |
| 最终提交 | 不自动提交 | 用户明确确认后提交 |
| Outlook同步 | 只读读取授权范围内邮件 | 用户授权和撤销授权 |
| 公开内推信息 | 读取用户发起搜索或提供的公开内容 | 用户确认来源和有效性 |

## 2. 主要风险

| 风险 | 影响 | 处理方式 |
|---|---|---|
| 登录信息泄露 | 用户账号被盗用 | 不保存密码，使用浏览器当前登录状态 |
| 页面结构变化 | 岗位或表单读取失败 | 采用网站适配器并提供手动复制兜底 |
| AI虚构经历 | 简历内容失真 | 事实库、锁定字段、修改差异和事实来源审查 |
| 错误投递 | 岗位、简历或链接不匹配 | 提交前展示岗位、链接、简历版本和状态 |
| 重复投递 | 影响用户申请记录 | 公司、岗位、批次和链接多维去重 |
| 内推码过期 | 投递失效或误用 | 保存来源、发布时间、适用范围和用户确认状态 |
| 邮件误判 | 投递状态错误 | 只读同步，保留原邮件入口并允许人工修正 |
| 功能扩张 | 研发范围失控 | 采用固定模块编号和三期路线图 |

## 3. 事实审计规则

公司名称、岗位名称、学校、学历、日期、语言成绩和量化数字属于受保护事实。任何岗位定制简历都必须保留修改前版本，展示修改差异，并能够回到事实库中的证据来源。

## 4. 操作审计

以下操作必须写入 `AuditEvent`：

- 用户授权或撤销授权；
- 岗位来源新增或删除；
- JD解析结果修改；
- 简历受保护字段修改；
- 表单字段填充；
- 高风险字段确认；
- 用户完成最终提交；
- 邮件状态自动识别或人工修正；
- 内推码候选被用户确认或拒绝。
