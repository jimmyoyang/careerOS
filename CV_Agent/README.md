# CV_Agent

CareerOS 求职投递工作台的独立产品工作区。

固定工作路径：`/Users/tang/Documents/Bid_Analysis/CV_Agent`。

本目录承载求职工作台的产品设计、数据模型、接口规范、分期 PRD、实现代码、测试和交付产物。原 `Bid_Analysis` 项目的业务分析代码、数据和文档保持原位置；后续与求职投递工作台相关的工作统一从本目录开始。

## 当前定位

CareerOS 面向多渠道求职者，支持从校园招聘官网、社会招聘官网或招聘平台页面开始，完成岗位读取、JD 解析、岗位匹配、简历适配、浏览器辅助填写和投递状态追踪。

产品采用三期渐进式建设：

1. 一期使用黑色实线，完成可靠的岗位到投递基础闭环。
2. 二期使用浅蓝色，增加多网站、批量处理、Outlook 只读同步和效率能力。
3. 三期使用浅绿色，增加招聘群、公开内推信息、内推码判断、多设备同步和个性化策略。

## 实施入口

总架构和三期规划定义长期范围，实际交付从一个用户、一个招聘网站、一个岗位的纵向试点开始。开发角色、交接和争议处理以协作治理文档为准，任务状态以一期执行台账为准。当前已决定将 Paperclip 作为中期协作控制面，但尚未完成本地部署验证、模型 Agent 接入或真实投递验收。第一条简历链路仍需先用脱敏资料验证。

## 后续工作原则

- PRD、模块规格和设计图源文件保存到本目录的 `docs/`；实现代码保存到 `src/`，测试保存到 `tests/`，交付产物保存到 `outputs/`。
- 上述路径均相对于 `CV_Agent`，不指向父级招投标项目的同名目录。
- 总架构先稳定，功能模块按阶段安装。
- 用户本人在浏览器中完成招聘网站登录，系统使用当前会话读取用户主动打开或授权的页面。
- 不保存招聘网站密码，不自动读取手机验证码，不绕过滑块验证，不未经用户确认完成最终提交。
- 简历改写必须来自用户事实库，关键事实需要可追溯。
- 每个模块先完成 PRD、数据字段、接口、异常处理和验收标准，再进入实现。
