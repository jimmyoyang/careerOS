# 多平台招聘工作台设计

## 目标

在现有手机接码登录和 CareerOS 数据模型之上，建立一个平台中立的登录后招聘工作台。华为招聘官网作为首个视觉和信息架构参考，后续可扩展字节、腾讯、阿里等来源；用户能够从统一入口管理简历、搜索职位、查看职位详情并跟踪投递进展。

## 范围与边界

- 保留现有 NextAuth 手机接码登录、Prisma 数据模型和已有 Profile/My Jobs/自动化/AI 能力。
- 不抓取需要登录的第三方页面，不代替第三方平台自动投递。
- 统一搜索查询当前 CareerOS 用户已有职位记录；来源值通过注册表归一化显示。
- 申请动作以已有职位跟踪为主，原始职位链接由详情页提供。
- 视觉使用华为招聘官网的红色强调、白底留白、主搜索入口和分类卡片，但产品名称和数据能力保持 CareerOS 中立。

## 用户流程

1. 登录后进入招聘工作台首页，看到欢迎区、简历状态、推荐职位入口、最近投递和来源分布。
2. 顶部全局搜索可跳转职位搜索页，并保留关键词。
3. 搜索页支持关键词、来源、地点和投递状态筛选，展示卡片/表格结果和总数。
4. 点击职位进入已有职位详情页，用户可查看描述、匹配简历、来源和原始链接，并继续现有状态/笔记/匹配动作。
5. Profile 页面继续支持简历创建、导入、编辑、复制、设为默认和导出。
6. 来源适配注册表为来源提供 label、色值、简称和可选外链元数据；未知来源回退到中性样式。

## 实现边界

- 新增来源注册表和展示组件，不改变已有来源数据库字段。
- 新增搜索页复用 getJobsList 与已有筛选数据，不创建第二套职位查询 API。
- Dashboard 改为招聘工作台首屏，保留现有统计、图表和最近活动组件。
- Header 增加统一搜索输入和“简历/搜索职位”快捷入口。
- 侧栏将 Profile、Jobs 和新增搜索入口分成清晰的招聘主流程。
- 所有新文案优先使用中文，同时保留已有英文数据标签可读性。
- 通过 TypeScript、ESLint、Vitest 和 Next build 进行验证。

## 错误处理与兼容性

- 搜索请求失败时沿用现有 toast 错误提示并保留输入。
- 来源未注册时使用默认蓝色圆标和来源名称。
- 没有简历/职位时展示可操作的空状态，不阻塞已有页面。
- 新页面必须在登录保护的 dashboard layout 内运行，不能绕过会话检查。
